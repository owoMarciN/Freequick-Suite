# Freequick — Rider App

Flutter mobile app for delivery riders. Receive dispatch jobs, navigate to restaurants and customers, and manage delivery status in real time.

---

## Setup

This app is part of the Freequick Suite mono repo. Complete the root-level setup first — FVM, `secrets.json`, and `firebase_options.dart` must all be in place before running.

### Required files

```
rider_app/
├── android/app/google-services.json     # Download from Firebase Console
├── ios/Runner/GoogleService-Info.plist  # Download from Firebase Console
└── lib/firebase_options.dart            # Generated by FlutterFire CLI
```

Generate `firebase_options.dart`:
```bash
cd rider_app
flutterfire configure --project=YOUR_FIREBASE_PROJECT_ID
```

### Run

```bash
cd rider_app
fvm flutter pub get
fvm flutter run --dart-define-from-file ../secrets.json
```

## Features

- Phone number authentication via Firebase OTP
- Profile setup with vehicle type selection (bicycle, scooter, car)
- Online / offline toggle
- Real-time dispatch job sheet with 30-second accept/reject countdown
- Cash collection warning — prominently alerts rider when payment must be collected from customer
- Active delivery screen with Google Maps, pickup and drop-off markers
- Step-by-step delivery stepper: In Progress → Ready → Delivered
- One-tap navigation to restaurant or customer via Google Maps app
- Earnings dashboard — today, this week, this month, all-time
- Average driver rating

## Architecture

```
lib/
├── extensions/            # BrandColors (shared definition with customer app)
├── models/                # DeliveryModel, OrderModel, OrderItem
├── providers/             # RiderProvider, RiderStatsProvider
├── screens/               # Home, active delivery, profile, setup
├── services/              # AuthService, RiderService
├── utils/                 # AppTheme, AppConstants, rider_global.dart
└── widgets/               # JobRequestSheet
```

### State Management

**`RiderProvider`** — mounted at app root in `main.dart`. Manages auth state, active order Firestore subscription, and pending dispatch job stream. The `RiderAppState` enum drives the entire navigation tree: `loading → unauthenticated → needsProfile → idle → onJob`.

**`RiderStatsProvider`** — streams all delivered orders for the current rider and computes earnings and delivery counts. Mounted only after authentication inside `_RiderShell` so `riderUID` is always valid.

### Navigation

No named routes. `_RiderShell` uses `IndexedStack` with a `BottomNavigationBar` for the Home and Profile tabs. When `appState == onJob` the active delivery screen replaces the shell entirely.

## Integrations

### Firebase
- **Auth** — phone OTP, session persistence
- **Firestore** — riders doc, orders stream, dispatch_jobs stream
- **Cloud Messaging** — dispatch job push notifications via `saveFcmToken`

### Google Maps
The active delivery screen renders a `GoogleMap` with markers for the restaurant (pickup) and customer (drop-off). The navigation button opens the Google Maps app with turn-by-turn driving directions.

---

## Order Status Flow

The rider controls two of the four status transitions:

```
Pending        ← set by Cloud Function on order creation
In Progress    ← set by Cloud Function when rider accepts dispatch job
Ready          ← rider taps "Picked Up" after collecting from restaurant
Delivered      ← rider taps "Delivered" after handing to customer
```

For cash orders the rider collects payment before marking as Delivered. The `collectPayment: true` flag on the dispatch job triggers a warning banner in the job request sheet.
