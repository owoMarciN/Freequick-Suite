# Freequick Suite

A full-stack food delivery platform built with Flutter and Firebase. The suite consists of three client applications and a shared backend, all managed in a single mono repository.

---

## Repository Structure

```
freequick-suite/
├── .fvm/                  # FVM Flutter version pin (3.38.9)
├── .vscode/               # VS Code launch configurations
├── customer_app/          # Mobile app for customers placing orders
├── merchant_app/          # Web dashboard for restaurant owners
├── rider_app/             # Mobile app for delivery riders
├── cloud_functions/       # Firebase Cloud Functions (TypeScript backend)
├── shared_assets/         # Shared fonts, images, and brand assets
├── firebase.json          # Firebase project configuration
├── firestore.rules        # Firestore security rules
├── .firebaserc            # Firebase project aliases
└── secrets.json           # ← NOT committed — see Environment & Secrets below
```

---

## Platform Overview

| App | Platform | Description |
|---|---|---|
| Customer App | iOS / Android | Browse restaurants, place orders, track delivery in real time |
| Merchant App | Web (Flutter Web) | Manage menus, handle incoming orders, view analytics |
| Rider App | iOS / Android | Receive dispatch jobs, navigate to restaurant and customer |
| Cloud Functions | Node.js (Firebase) | Payment processing, order dispatch, push notifications |

---

## Tech Stack

### Frontend
- **Flutter 3.38.9** (pinned via FVM) — all three client apps
- **Provider** — state management across all apps
- **Firebase Auth** — phone number OTP authentication
- **Google Maps Flutter** — live delivery tracking and navigation

### Backend
- **Firebase Firestore** — real-time database for orders, riders, restaurants
- **Firebase Cloud Functions** — TypeScript backend for business logic
- **Firebase Cloud Messaging** — push notifications to all three apps
- **Firebase Storage** — restaurant logos, banners, and profile photos

### Third-party Integrations
- **Stripe** — card payment processing via Firebase Stripe Extension
- **Algolia** — restaurant and menu item search with instant results
- **Google Maps Platform** — Directions API for ETA and route polylines
- **Google Translate** — automated ARB localisation file generation

## Prerequisites

### 1. Install FVM

All three Flutter apps are pinned to **Flutter 3.38.9** via FVM. Install FVM first:

```bash
# Install FVM globally
dart pub global activate fvm

# From the repo root — installs the pinned Flutter version
fvm install

# Verify
fvm flutter --version
```

> From this point use `fvm flutter` instead of `flutter` for all commands,
> or configure your IDE to use the FVM SDK path (`.fvm/flutter_sdk`).

#### VS Code
Add to `.vscode/settings.json` (already included in the repo):
```json
{
  "dart.flutterSdkPath": ".fvm/flutter_sdk"
}
```

#### Android Studio
Go to `Settings → Languages & Frameworks → Flutter` and set the SDK path to:
```
/path/to/freequick-suite/.fvm/flutter_sdk
```

---

### 2. Firebase Config Files

Each Flutter app needs Firebase config files that are **not committed** to the repo. Obtain them from the Firebase Console under **Project Settings → Your Apps**.

#### Android — `google-services.json`
```
customer_app/android/app/google-services.json
merchant_app/android/app/google-services.json
rider_app/android/app/google-services.json
```

#### iOS — `GoogleService-Info.plist`
```
customer_app/ios/Runner/GoogleService-Info.plist
merchant_app/ios/Runner/GoogleService-Info.plist
rider_app/ios/Runner/GoogleService-Info.plist
```

#### `firebase_options.dart`
Generated by the FlutterFire CLI. Place in `lib/` of each app:
```
customer_app/lib/firebase_options.dart
merchant_app/lib/firebase_options.dart
rider_app/lib/firebase_options.dart
```

To regenerate:
```bash
# Install FlutterFire CLI
dart pub global activate flutterfire_cli

# Run from inside each app directory
cd customer_app
flutterfire configure --project=YOUR_FIREBASE_PROJECT_ID
```

---

### 3. Secrets

Create `secrets.json` in the **repo root** (never commit — it is in `.gitignore`):

```json
{
  "STRIPE_SECRET_KEY": "sk_live_...",
  "STRIPE_PUBLISHABLE_KEY": "pk_live_...",
  "STRIPE_WEBHOOK_SECRET": "whsec_...",
  "MAPS_API_KEY": "AIza...",
  "ALGOLIA_APP_ID": "...",
  "ALGOLIA_SEARCH_KEY": "..."
}
```

Flutter apps read this at build time via `--dart-define-from-file ../secrets.json`.
Cloud Functions read it at runtime from `../../secrets.json` relative to the compiled output.

## Getting Started

```bash
# 1. Clone
git clone https://github.com/owoMarciN/freequick-suite.git
cd freequick-suite

# 2. Install pinned Flutter version
fvm install

# 3. Add Firebase config files to each app (see above)

# 4. Add secrets.json to repo root (see above)

# 5. Install Cloud Function dependencies
cd cloud_functions && npm install && cd ..
```

### Run the Merchant Dashboard (web)
```bash
cd merchant_app
fvm flutter pub get
fvm flutter run -d web-server --web-port 8080 --dart-define-from-file ../secrets.json
# Open http://localhost:8080 in any browser
```

### Run the Customer App (mobile)
```bash
cd customer_app
fvm flutter pub get
fvm flutter run --dart-define-from-file ../secrets.json
```

### Run the Rider App (mobile)
```bash
cd rider_app
fvm flutter pub get
fvm flutter run --dart-define-from-file ../secrets.json
```

### Deploy Cloud Functions
```bash
cd cloud_functions
npm run build && firebase deploy --only functions
```

### Deploy Firestore Rules
```bash
firebase deploy --only firestore:rules
```

## Firebase Setup

Single Firebase project shared across all three apps.

### Some of the Firestore Collections

```
orders/{orderID}
users/{uid}/orders/{orderID}
users/{uid}/notifications/{id}
restaurants/{id}/menus/{menuId}/items/{itemId}
restaurants/{id}/promotions/{id}
riders/{uid}
dispatch_jobs/{jobID}
```

### Security Rules
Firestore rules are in `firestore.rules`. Key principles:
- Restaurant owners can only write to their own documents
- Menus and items can only be written when restaurant `status == 'Active'`
- Admins approve restaurants by setting `status: 'Active'` only
- Riders can only update their own dispatch jobs, status field only
- Order status can be updated by the customer, restaurant, and assigned rider
